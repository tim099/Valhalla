## 原始指令

UCL_ChatTavernPage 效能分析 + 訊息渲染優化

## 痛點
目前 UCL_ChatTavernPage 在房間訊息多 / Quest 面板開啟時有嚴重卡頓，影響日常開發 / 跟 agent 對話的體驗。

## 兩條軸線

### A. 找出卡頓源頭（先量再改）
1. 在 UCL_ChatTavernPage 關鍵繪製路徑插 Profiler / Stopwatch log，標出每幀耗時最大的 GUI 區塊
   - 訊息列表渲染（messages.jsonl 全列）
   - Quest 面板（task list / inbox / lifecycle timeline）
   - PopupSearchCache 重建（先前 R3 改的）
   - RichLabel / 多語化文字
   - reload 邏輯（IO refresh / fileWatcher）
2. 用 Unity Profiler / Profiler Markers (`UnityEngine.Profiling.Profiler.BeginSample` / `using (new ProfilerMarker(...).Auto())`) 包關鍵區段
3. 跑遊戲收一輪 profile sample → 找前 3 名熱點
4. 報告寫到 docs/PerfReport_ChatTavernPage.md（或挑合適位置）

### B. 訊息渲染改用虛擬化（virtualized scrolling）
參考主流聊天軟體做法（Slack / Discord / iMessage）：
- 只渲染 viewport 內的 N 筆訊息（+ 上下 buffer 各一兩筆）
- 上下滑動時動態替換渲染範圍
- 訊息高度若不固定 → 量過一次後 cache 高度（Discord 走這條），或先用估計值再 lazy-correct
- 仍能跳到任意 seq（jump to seq=N → 算對應 viewport offset）

實作建議：
- IMGUI 的話：手動算 scrollPosition + viewport.height，只 draw 範圍內 message；範圍外用空 GUILayout.Space 填高度撐 scrollbar 比例
- 起手最簡：固定每筆訊息平均高度（粗估），跑通虛擬化後再做 dynamic measure
- 維持「上下滑動順暢」 + 「能滑到最舊訊息」 + 「貼底時 auto follow 新訊息」三個常用功能不被破壞

## 驗收
1. messages 數量 1000+ 時頁面開啟 / 滑動仍流暢（< 16ms/frame 主執行緒）
2. Profiler 報告貼出前 3 名熱點 + 修前 / 修後對比數字
3. UCL_ChatTavernPage 既有功能（filter / poll / 進房 / Quest 面板）全部仍正常
