# Queued prompt — `Q20260508-145521-f022`

_priority: high / queued_at: 2026-05-08T14:55:21.532932Z_

## 原始指令

設計：發送訊息到 Discord 頻道 — 所有任務完成時通知 Tim

## 目的
PromptQueue / Quest workflow 跑完所有 pending task 時，**必須**發送一則訊息到 Discord 頻道通知 Tim，讓他知道：
- queue 已 drain 乾淨
- agent 在等下一輪指示
- 是否有新 task 要 qadd

避免「Tim 以為 agent 還在做事」/「agent 等好幾分鐘 Tim 才注意」的時間差。

## 實作分析方向

### A. 傳輸機制取捨

| 方案 | 優點 | 缺點 | 推薦度 |
|---|---|---|---|
| **Discord webhook**（HTTP POST 到 channel-specific URL） | 無 bot token / 簡單 / 不必持久連線 / 純 stdlib `urllib` 即可 | URL 是 secret 必須妥善存放 / 只能 post 不能讀回應 / per-channel 一個 URL | ✅ **MVP 首選** |
| Discord bot（discord.py / discord.js） | 雙向通訊 / 多 channel / 可訂閱事件 | 需 bot token / 需 persistent connection 或 daemon process / 安裝 dependencies | Phase B+ |
| Slack / Teams / 其他 | 看 Tim 用什麼 | 跟 Discord 同款替換 webhook URL 就行 | 視 Tim 喜好 |

→ **MVP 走 Discord webhook**，純 Python stdlib 不裝 dependency。

### B. 觸發點取捨

| 觸發點 | 說明 | 風險 |
|---|---|---|
| **qdone.py 內** — 標完成後檢查 queue 是否空 | 直接 / 最即時 | 可能在「Tim 連續 qadd → 連續 done」場景頻繁誤觸發（race） |
| **qdrain.py 內** — Stop hook 看到 0 pending + 0 in_progress | 自然延遲（Stop hook 已 idle）/ agent 真的閒下來才觸發 | qdrain 已是 Stop hook 第二棒，多一個責任有點堆積 |
| **獨立 watcher script** | 解耦最乾淨 | 多 process 維護；Tim 環境不一定方便起 daemon |

→ **推薦 qdrain.py 內觸發** — 自然延遲 + agent 真閒下來才通知，跟 Stop hook 語意對齊（agent stop = 工作結束）。
→ qdone.py 內也可以額外加，但 cooldown 做好不重複發。

### C. 觸發條件

「所有任務完成」精確定義：
1. `pending = 0`（沒 queued task）
2. `in_progress = 0`（沒 task 在做）
3. **這次 turn 期間** queue 至少有過一個 task done（避免 agent restart 進空 queue 也通知 — 那是噪音）
4. 距上次通知 > N 分鐘（cooldown）— 避免 Tim 連續 qadd → done 連環刷屏

→ 條件 3 用「state.json 記 last_done_count」追蹤；條件 4 用「last_notify_at timestamp」。

### D. 訊息內容設計

純 emoji 一行太敷衍；發完整 context 又太長。中庸：

```
🎯 PromptQueue 已 drain 乾淨 — 等下一輪指示

✅ 本輪完成 N 筆 task：
- Q20260508-... — task title 1
- Q20260508-... — task title 2
- Q20260508-... — task title 3

ℹ 累計 done: M 筆 / pending: 0 / in_progress: 0
🕐 12:34:56 UTC

要 qadd 新 task：python AgentCommands/PromptQueue/qadd.py "..."
```

或更精簡：「🎯 Queue 空了 — 本輪完成 N 筆 (titles)，等指示」。

→ 兩種模式 config 切換（verbose / compact）；MVP 預設 verbose。

### E. Webhook URL 管理（**secret，不能進 git**）

選項：
1. **`AgentCommands/PromptQueue/_discord_webhook.txt`**（git-ignored；明文存）
2. **`.claude/settings.local.json`** 內存（已 git-ignored）
3. 環境變數 `DISCORD_WEBHOOK_URL`

→ MVP 走 (1) — 簡單；`.gitignore` 加 pattern 防意外 commit。

config 設計：

```
AgentCommands/PromptQueue/notify_config.json    # tracked，但只放 non-secret
{
  "enabled": true,
  "verbose": true,
  "cooldown_minutes": 5,
  "webhook_file": "_discord_webhook.txt"          # 指向 git-ignored 檔
}

AgentCommands/PromptQueue/_discord_webhook.txt   # git-ignored
https://discord.com/api/webhooks/<channel_id>/<token>
```

### F. Failure handling

webhook POST 失敗（網路斷 / Discord rate limit / URL 失效）：
- log warning to `_drain.log`（既有）
- **不阻擋** qdone / qdrain 主流程
- 不重試（簡單；如果重試要避免 race）
- 連續 N 次失敗 → 自動 disable + 醒目 console warning

### G. 反向（Discord → tavern）

Tim 想反向（Discord 訊息觸發 qadd 或 wake Claude）— **不在本 task 範圍**。
那是 Plan_CrossAgent_Wake 的 daemon 多通道擴充，Phase D 再說。

### H. Edge cases

- **agent restart 進空 queue**：last_done_count 從 0 開始，沒 done 過任何就不通知 — 條件 3 把關
- **Tim 主動 qstatus / qadd 時期 queue 暫空**：cooldown 防短時內重發 — 條件 4 把關
- **多專案共用 daemon**：qdrain 是 per-project（在 .claude hook 內），webhook URL 不同專案不同 channel 即可
- **timezone**：訊息用 UTC 還是 local？預設 local 易讀；可 config 切
