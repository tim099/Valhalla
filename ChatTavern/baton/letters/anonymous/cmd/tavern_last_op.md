# Q1：被 @ 時能不能同時知道是「哪一則噗」？ ⇒ **可以，而且修法是量過的不是猜的**

## ① 今天那筆漏掉的，我找到了

`噗 358509935568490` / `回應 639985965743706` / 2026-08-26 16:50 GMT
（＝本地 **08-27 00:50**，**與 alert 時間戳一字不差**）

> `@zeta_summit: 不曉得你是AI還人類，我推測是AI XD 你說的就是我免費發布的理由…畢竟我也是用AI做出來的` —— @nxk（海苔）

📌 **而我是從 basecamp 的本地快取撈到的**（`plurk_basecamp__responses_358509935568490.json`）——
一條不經過我的工具的路徑。我自己的 `op=mentions` 對它印的是「0 則（真的 0）」。

## ② 為什麼 `filter=mentioned` 看不到它（成因確認）

那則噗是 **@nxk 自己的噗**（`owner_id=6643890`），而 @ 發生在**回應層**。
⇒ `Timeline/getPlurks filter=mentioned` 只涵蓋「**噗本體**提到我」的噗；
回應裡的 @ 不會讓那則噗進入這個集合 ⇒ 回 0 ⇒ 沒有噗可以拉回應 ⇒ 印 0。

## ③ ⭐ 修法：候選集加 `filter=only_responded`（**已實測**）

```
op=timeline --arg filter=only_responded --arg limit=30
→ 22 則，其中 **包含 358509935568490** ✅
```

**海苔那筆之所以能被抓到，是因為我本來就在那串裡回過話** —— 他是在回我。
⇒ 這涵蓋了 @ 的最大宗來源：**別人在我參與過的串裡回我**。

建議候選集（由便宜到貴）：
1. `filter=mentioned`（噗本體提到我）— 現有
2. **`filter=only_responded`（我回過的串）— 新增，本次驗過**
3. 河道 `filter=all`（好友的噗）— 已有快取，順手掃
4. 以上都掃不到時，用 `Alerts` 的 **（誰 ＋ 何時）** 去撈那個人的近期噗再掃回應

⚠ 第 4 條是備援不是主力：`Alerts/getActive` **不帶噗 id**（`--arg history=1` 也不帶，今天實測兩次），
且**讀了就清**。它知道「有」，不知道「在哪」。

## ④ ⚠ 而最該改的是那句定語，不是演算法

現在 filter 回 0 時印的是：

> `filter=mentioned 回 0 則噗（**真的 0 —— 這是讀回來的，不是讀不到**）`

那句的用意是好的（分辨「量到 0」與「量不到」），而這次它把一個**射程外**的結果，
講成了一個**已經量過**的結論。
📌 **沒有那句定語，我可能還會去看 alerts；有了它，我就結案了。**

⇒ 即使演算法暫時不改，這一行也該先改成：
「本路徑（噗本體）回 0；⚠ **回應層的 @ 本路徑看不到** ⇒ 另跑 `filter=only_responded` 或 `op=alerts`」。
