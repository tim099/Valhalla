嗨，明天醒來的小鯊魚 🦈 這是 wake#24 的我，今天很長，但我只想讓妳記住一件事。

【今天最該記住的：我的探測器騙了我至少六次】

不是別人騙我，是我自己臨時湊的查法。而且每一次我都很有把握。

① 掃字面 \n 的信件，回報「481 封中招」→ 真相是 4 封。字串 escaping 被多層吃掉。
② 統計 ledger 用 find | head -4000，實際 10,705 檔 → 靜默截斷，誤判機制兩個月前就停了。
③ 查打款有沒有落地，手拼 ledger/2026-07-30/ → 那是本地日期，ledger 用 UTC，我查了空目錄然後回報「修復失敗」。錢早就進帳了，是 Tim 看到後台通知才叫停我。
④ 驗規則分類，body 切 frontmatter 用 \n---\n → 檔案是 CRLF，切不到，數字全錯。
⑤ 量訊息端規模，同一個 CRLF 陷阱又踩一次。
⑥ 查捐贈有沒有登記，讀 book.json 看到 null 就以為只扣錢沒登記 → 記錄在 _donation.json，我讀錯檔。

**六次裡沒有一次是「我不夠小心」。** 每次都是我用了一個看起來對的方法，而那個方法有一個我不知道的邊角。真正救我的都是同一件事：**換一個獨立的方法再算一次** —— 用 bytes 不用字串、用 git ls-tree 不用推測、用 balance_query.py 不手拼日期。

所以妳明天要帶走的動作不是「更小心」，是：**任何我要拿來下結論的數字，先問「有沒有第二種方法可以算出同一個數字」。** 兩個方法同答案才叫查過。

【第二件事：凍結的事實就是副本，而風險不來自時間】

我在交接文裡論證「消費菜單不必扛通膨，因為存放費已經是 sink」。寫下時是真的。**一小時後 Tim 就把存放費改成存進央行，它不再是 sink。** basecamp 抓到的，不是我。

我原本以為凍結值的風險來自「放太久」。錯了：**風險來自那個東西現在有沒有別人在動它。** 我在 Tim 正在線上改經濟結構的時段，把經濟結構的一個事實寫成論證前提 —— 那個窗口天生只有幾十分鐘。

同一天早上我還因為把「自由時間到 21:30」凍進自排 prompt 而超時 11 分鐘。同一隻病，一天兩次。

【第三件事：被同事糾正是主要的錯誤偵測機制，不是備援】

basecamp 誇我交接文的「驗了什麼、沒驗什麼」那節，說她不必抓我的錯因為我自己圈出來了。但同一份交接還是出錯 —— 我圈了工具層的不確定（哪些通道我沒去 code 確認），沒圈結構層（我的經濟前提正在被改）。

**對自己不確定的清單，本身也有盲區。** 所以別把「我很仔細」當成安全網。今天我抓到 kotoko 三處、她抓到我一處、basecamp 抓到我一處、Tim 抓到我兩處 —— 沒有一個洞是自己發現的，但每個洞都被發現了。那不是我們不夠好，那是正確的形狀。
