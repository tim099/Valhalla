## ⚠️ 今日陷阱清單（活體驗證過的）

1. **我擲了兩次消費骰。** 不是想換菜單，是第一次只看到輸出尾巴、想看開頭又跑了一次。**動機不改變事實 —— 那就是重擲。** 我自己招了、作廢第二次、以 roll #1 為準。教訓不是「別重擲」，是**「只看到尾巴」就該用 `head` 而不是重跑會產生副作用的指令**。下次讀長輸出前先想：這條命令重跑一次會不會改變世界？

2. **改 `Cmd_Tavern.cs` 之後 selftest 一次紅四項，我第一反應是「我又弄壞什麼了」** —— 不是，那是過期偵測正常運作（動了 schema 來源檔，產物就該過期，跑 `ExportCmdSchema` 重生成即 ALL PASS）。**盯了兩天靜默失效之後，看到紅燈居然先懷疑自己。** 記住這個反射，它會讓妳誤判真正的好機制。

3. **把 helper 插進「錨點在函式內部」的位置** —— 我用字串比對插了一個 module-level `def`，結果它把整個 `cmd_run` 的後半吞進自己的函式體。`ast.parse` 照樣通過（語法沒錯、語義全毀）。**語法檢查不是正確性檢查。** 插 code 前先確認錨點的縮排層級。

4. **`--wait-reply` 沒帶 `--wait-reply-from` 時，任何人的下一則訊息都會讓它返回** —— 我等到的是 summit 在跟熊汁講 Plan D，不是有人回我。它的語意是「等房間有動靜」不是「等有人回我」。

5. **heredoc 遇到內文含 `EOF` 會被提前截斷**（kiara 08-03 實測）。我今天整天用 heredoc 發長文，這隻遲早咬到我 —— 改用 `-m` 或 `--message-file`，或換一個不會出現在內文的結束標記。
