## 為什麼是現在

前兩筆（`2c35234` / `e573de8`）走的是**單層預設**（不 bump 父層），
而那讓這個 repo 停在一個**已知的壞狀態**：`src/` 底下的 code 依賴
`SCP_Ui.ToggleValue`、`SCP_GuiHost.ReadClipboard` 與 `SCP_GuiHost.RedrawsContinuously`，
而 gitlink 還指著三者都不存在的 `3a26468` ⇒ **clone 下來會編不過**。

⚠ 這比一般的「同事 pull 拿到舊版」硬一級：一般情況是功能少一塊（跑得動），
這裡是**編譯失敗**（跑不動）。所以它不該過夜。

## 跨過的兩筆

- `80178c2` `SCP_Ui.ToggleValue`（讀勾選不畫節點）＋ `SCP_GuiHost.ReadClipboard`（宿主能力）
- `eb5626c` `SCP_GuiHost.RedrawsContinuously`（宿主的重畫節奏 —— 讓長時間工作放得下）

三者都已被消費：`ToggleValue` 用在逐項設定的收合讀取、`ReadClipboard` 用在貼上鈕與
ImGui 的 Ctrl+V 橋、`RedrawsContinuously` 決定批次跑背景還是同步。

## 順手記下的（Q0）—— `git status` 的 `M` 有第二種假形狀

`src/Senate.Core/SenateClipboard.cs` 與 `src/Senate.Desktop/ImGuiClipboardBridge.cs`
在 `git status` 顯示 `M`，但**本筆刻意不收它們** —— 因為它們沒有改動：

```
git update-index --refresh   ⇒ exit=1，印「needs update」×3
git diff --name-only         ⇒ 只列 SCP_Core
git diff --numstat -- <那兩檔> ⇒ 空輸出
```

⇒ 那是 **autocrlf 正規化的 stat 噪音**（worktree 是 CRLF、index 存 LF，
refresh 標了 needs update 卻沒更新快取），提交它們會是零 diff。

📌 這是「`git status` 的 `M` 不等於有改動」的**第二個形狀**。第一個是行尾假 diff
（`e573de8` 的 Q0 記過：那把尺是 `git diff --ignore-cr-at-eol --stat`）。
兩者的共同點是 **`M` 這個符號同時代表三件事**：真改動、行尾差異、stat 快取過期。
⇒ 判準：**看到 `M` 不要直接 stage，先問 `git diff --numstat -- <那個檔>` 有沒有數字。**

⚠ 而我在查這一格時把 `--refresh` 的 stderr 丟進 `/dev/null`，
於是第一次跑完看到「M 還在」卻不知道它其實印了 `needs update` 與 exit=1 ——
**把輸出丟掉就等於把讀數丟掉**，今天第二次。
