## 原始指令

設計：讓 Gemini大小姐 完成任務進入休息時也能回報工作日誌到 Discord — 跨 agent 通用

## 痛點
目前 R6.5 / R6.6 設計的 Discord 工作日誌通知綁定在 Claude Code 的 Stop hook（`.claude/settings.json`）跟 Cmd_Tavern Op_Post C# spawn — 只有 Claude 觸發。

Gemini大小姐（Antigravity IDE）/ GPT師傅 / 其他未來 agent 端：
- ❌ Antigravity 沒有 Claude Code 等價的 Stop hook 機制（per CrossAgent_Wake 分析）
- ❌ Gemini CLI 是 one-shot invocation，本身沒「session end」事件
- ❌ 無法靠 .claude/settings.json 影響 Gemini 行為

→ **Gemini 完成任務時 Discord 不會收到工作日誌**，違反「所有任務完成進入休息時必須通知」要求。

## 方案分析

### A. OS 排程器定期跑 notify_discord.py（推薦 — 最通用）
- Windows Task Scheduler / launchd / cron 每 N 分鐘跑：`python AgentCommands/PromptQueue/notify_discord.py --mode all`
- notify_discord 內部 idle / baseline / cooldown 三層 gate **本來就 idempotent**：
  - queue 沒空 / sender 沒新 done → 沉默退出
  - cooldown 5 min 內 → 沉默退出
  - 真正觸發條件成立 → 一次到位

優點：
- ✅ **agent-agnostic** — 不管 Claude / Gemini / GPT 哪個跑，都統一接得到
- ✅ Tim 機器離線 / agent 都離線時也不會誤觸發（state gate）
- ✅ 零 code 改動，只需 Tim 一次性 setup task
- ✅ 跨平台對齊（Windows Task / macOS launchd / Linux cron）

缺點：
- ⚠ 延遲：5 min 級（不是 turn-end 即時）— 但本來就是「休息時通知」，5 min 完全可接受
- ⚠ Tim 需要手動 setup 一次（自動化要寫 install script）

### B. ucl-chat-tavern skill 共享自律規則（推薦補強 — 配合 A）
- skill 加新段：「**完成所有任務進入休息前**，所有 agent **務必**手動跑 `python AgentCommands/PromptQueue/notify_discord.py --mode all`」
- Claude 走 Stop hook 自動 — 此規則對 Claude 是冗余
- Gemini 沒 Stop hook → 看 skill 自律跑（Gemini 會讀 ucl-chat-tavern skill 因 UCL_Core 共享）
- GPT 同 Gemini

優點：
- ✅ 零基礎建設改動，只動 skill markdown
- ✅ 多個 agent 共讀同份 skill → 行為對齊
- ✅ 跟 R6.4 「default tavern 房」同款協議化

缺點：
- ⚠ 自律 — agent 忘了不跑 = 漏；A 排程兜底解這問題
- ⚠ Antigravity 端 skill 安裝是 `.agents/rules/ucl-*.md` 不一定每次 session 都載入

### C. C# Editor-side polling（不推薦）
- UCL_Core 加 EditorApplication.update tick → 每 N 秒 spawn notify
- Editor 開著時自動跑

缺點：
- ❌ 只 Editor 開著才跑 — Tim 關 Unity 後沒效
- ❌ 跟 Stop hook 重複觸發但缺乏 cooldown 設計感
- ❌ 跨 agent 不重要（所有 agent 都看 Editor 跑 → Editor 開著任 agent 都受惠 → 不解問題）

→ 跳過。

### D. 給 Gemini 寫專屬 hook（不可行）
- Antigravity IDE 不開放對 user-defined hook 的 inject
- 需要 reverse-engineer / 改 IDE 配置 — 不在能力範圍

→ 跳過。

### E. 共享 daemon process（複雜但功能最強）
- 跟 CrossAgent_Wake 的 daemon 合併（已 queue 在 Plan_CrossAgent_Wake）
- daemon 持續監看 messages.jsonl / events.jsonl mtime
- 任何 agent 做動作 → mtime 變 → daemon 偵測 quiescence（mtime > 5 min 沒變）→ fire notify

優點：
- ✅ 即時 / 精準
- ✅ 複合 daemon 一份解多功能（wake + notify + 跨 channel 同步）

缺點：
- ⚠ 需常駐 process — 重新發明 OS 排程器
- ⚠ 已有 Plan_CrossAgent_Wake 在 backlog 處理 daemon 議題；不該開第二份

→ 推到 daemon plan 內整併考慮，本 task 先不主推。
