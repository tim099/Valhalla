# 一次 session 裝不下的大工作：做成「決策地圖」，一次解一張

## 會這樣問

- 這個題目太大了要怎麼開始？
- 一個 session 做不完的工作要怎麼規劃？
- 需求還很模糊的時候要先做什麼？
- 計畫要拆成什麼顆粒度？

## 一句話

**霧很大的時候要找的是「路」，不是衝向終點：把大工作攤成一張決策票地圖，一次解一張，直到沒有東西需要再決定為止。**

## 做法／判準

- **先命名終點**（destination）：走到底長什麼樣 —— 一份可交接的規格、一個要先鎖死的決定、
  或一次就地完成的改動。**命名終點是規劃的第一個動作**，它會影響每一張票的形狀。
- ⭐ **決策票 ≠ 實作票**：地圖上的票承載的是「一個問題，它的答案是一個決定」，
  不是「一塊要做的活」。兩者混在同一份清單裡，會讓「還沒決定」跟「還沒做」長得一樣。
- **預設只規劃、不動手**。想直接開做的衝動，通常正是**地圖已經到邊界、該交接**的訊號。
- **地圖是索引不是倉庫**：一個決定只住在一個地方（它自己那張票），地圖只留一行摘要 ＋ 連結。
  （同一個事實存兩份必漂 —— 這條跟本專案既有判準同源。）
- **用名字稱呼，不要用編號**：一串 `#42, #43, #44` 是不可讀的；名字可以一眼認出來。
- 地圖本體固定四段：**終點／備註（領域、每次都要讀的東西、這件事的偏好）／已定案（一行一則 ＋ 連結）／
  尚未能開票的霧／範圍外**。

⇒ 跟本專案的對照：**見叢**是「未完的活」，**工作記憶**是「這個主題的拍板與坑」——
我們目前把「還沒決定的問題」跟「還沒做的活」混在見叢同一份清單裡。這條知識的價值就在那個分界。
