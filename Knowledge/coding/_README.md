# Knowledge / coding —— 外部提煉的工程知識（KB target `coding`）

**這裡不是 skill，是知識點。** 我們刻意不把外部 skill 搬進專案（那會多一份要同步的東西），
只提取其中的**判準與做法**，寫成可被語意檢索的碎片 —— 需要時用問句撈回來。

## 一檔一個知識點

檔名 `<slug>.md`，內容固定四段：

| 段 | 作用 |
|---|---|
| `## 會這樣問` | **檢索鉤子** —— 列真人會打的那幾句問法（句子，不是關鍵字）。⚠ 這段不是裝飾：bge-m3 比對的是語意，而「我要怎麼處理 merge conflict」跟一份只寫 `git rebase --continue` 的技術筆記在向量上並不近。 |
| `## 一句話` | 這條知識的骨。 |
| `## 做法／判準` | 可照做的步驟或可判定的界線。 |
| `## 出處` | 外部來源與**我讀到哪**（讀了原文 vs 只看 description）。 |

## 規矩

- **來源要標，讀到哪也要標。** 只看 description 就寫的東西，要寫明它是二手的。
- **不抄原文整段。** 提煉成自己的話 ＋ 指回原始出處，否則這裡會變成一份會過期的副本。
- 前綴 `_` 的檔（本檔）**不進索引** —— 它是說明不是知識。

低分是誠實的訊號，但只有知道邊界的人讀得出來。

- ⛔ **我們自己的血證**（踩過的坑、跨層驗證、假綠家族）→ `fragments` / `lessons` / `alaya`
- ⛔ **本專案的機制與 API**（Cmd / 路徑解析 / 帳本）→ `coredocs` / `docs`

- ✅ 這裡只收**外部提煉的通用工程實務**：怎麼解衝突、怎麼建 debug 迴路、測試該寫在哪、
  介面該多深、review 怎麼分軸、寫給 agent 的文件怎麼寫。

⇒ 撈到的東西分數低於 ~0.6 又不在上面那份清單裡，多半是**問錯庫**，不是知識不存在。
