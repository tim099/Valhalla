# Deep module：介面小、實作厚，以及「seam 該畫在哪」

## 會這樣問

- 這個模組介面該長怎樣？
- 這段 code 該切在哪裡？
- 要不要為這個東西抽一層介面？
- 怎麼判斷一層抽象有沒有價值？
- 為什麼加了一層之後反而更難改？

## 一句話

**深模組 ＝ 小介面 ＋ 厚實作；淺模組 ＝ 介面幾乎跟實作一樣複雜（那層是純轉手，該刪）。**

## 做法／判準

**詞彙（刻意精確，不要換成「元件／服務／API／邊界」）**
- **Interface** ＝ 呼叫端為了正確使用**必須知道的全部**：型別簽章、不變式、順序限制、錯誤模式、
  必要設定、效能特性。（不要說 API／signature —— 那兩個只指型別層那一面，**太窄**。）
- **Depth** ＝ 介面的槓桿：呼叫端每學一單位介面，能操作多少行為。
- **Seam** ＝ 你**可以在別處改變行為而不必改到這裡**的那個位置；「seam 畫在哪」是獨立於
  「seam 後面放什麼」的另一個設計決定。
- **Leverage**（呼叫端拿到的）／**Locality**（維護者拿到的：改動、bug、知識、驗證都集中在一處）。

**判準（可直接套）**
- **深淺是介面的性質，不是實作的。** 深模組內部照樣可以由一堆小的、可替換的零件組成 ——
  只要那些零件**不在介面上**。模組可以有**內部 seam**（給自己的測試用）與**外部 seam**（介面）。
- **刪除測試**：想像把這個模組刪掉。複雜度跟著消失 ⇒ 它是純轉手；複雜度**跑到 N 個呼叫端重新長出來**
  ⇒ 它有在賺錢。
- **介面就是測試面**：呼叫端與測試穿過同一個 seam。**你想測到介面之後面去，通常代表模組形狀不對。**
- ⭐ **一個 adapter ＝ 假想的 seam；兩個 adapter 才是真的 seam。** 沒有東西真的在那條線上變動，
  就不要開那條線。

**設計介面時問**：方法能不能更少？參數能不能更簡單？能不能把更多複雜度藏進去？
