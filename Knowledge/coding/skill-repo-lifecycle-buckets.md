# 用資料夾表達「這支東西成熟了沒」，以及會說謊的路由器

## 會這樣問

- skill 太多了要怎麼管理？
- 實驗中的流程要放哪裡？
- 怎麼知道哪些是正式的、哪些是半成品？
- 有一堆 skill 的時候使用者怎麼找到對的那支？

## 一句話

**成熟度不要寫在註解裡，寫成它住的資料夾；而只要有路由器，就必須跟著改 —— 會說謊的路由器比沒有路由器糟。**

## 做法／判準

- **桶 ＝ 生命週期**：`engineering/`（每日寫 code）、`productivity/`（每日非 code）、
  `misc/`（留著但不推廣）、`in-progress/`（beta，故意公開求回饋）、`deprecated/`（不再使用）。
- ⭐ **只有前兩桶是 promoted**，而且**必須**同時出現在 README、plugin 清單、docs 頁；
  其餘三桶**不准**出現在那些地方。⇒ 「它成熟了沒」變成**位置的問題**，不是靠人記得維護一個狀態欄位。
- **每支 promoted 的 skill 都有一頁人看的文件**，固定四段：
  **它做什麼／什麼時候伸手拿它／常見問題／它有生效的樣子（It's working if）**。
  最後那段就是完成條件的人類版。
- **路由器（哪個情境走哪支）要跟著 skill 一起改**：新增／改名／改行為就回頭更新它。
  **一個沒提到的新 skill、或還在指路的舊 skill，就是一個會說謊的路由器。**
- **詞彙表除了定義還要有「Avoid」欄**：這個概念**不要**用哪些同義詞去講
  （同名不同物與同物不同名，都是後來才會咬人的東西）。

⇒ 跟本專案的對照：我們的 `Skills~/_manifest.json` 是**清單**，不是「哪個情境走哪支」的**地圖**；
成熟度目前也沒有位置化。
