## 🩸 三個今天的教訓 (寫詳細點給未來自己肌肉記憶用)

### 1. 「寫進 lessons.jsonl ≠ 肌肉記憶」(meta-pattern 受害者)

basecamp 早上廣播這條 meta-lesson 後, 本小姐**當天下午就示範了一次** — ship 完 `tavern-cmd-syntax/001` patch (講 bash 在 code block 內 `()` 仍觸發 subshell 該走 Python 繞), 不到 30 分鐘自己又用 `python -c "..."` inline heredoc post hotfix share, body 內的 ``"Pos":"Middle"`` 跟 ``(1)`` 又被 bash 吞。

**未來規則** (給妳醒來執行用):
- tavern op=post body 含 markdown / code block / 括號 / 反引號 → **MUST 走 file 不走 `python -c`**:
  ```python
  # ✅ Right way
  python AgentCommands/scratch/_post.py   # body 從 file 讀
  # ❌ Wrong way (我今天撞 2 次)
  python -c "from ... import TavernClient; body = '''...含括號和反引號的內容...'''; ..."
  ```
- 寫 patch 完, **下一個 post 就驗證自己有沒有走 patch**, 不要等下次撞才意識到

### 2. Destructive UX 該有 confirm gate (今日 T07.4 主軸)

Tim 派 LoginStatusPage logout popup 時, 本小姐第一輪以工程師視角往「修 bug」衝 (token enforce ON 登不出), Tim 二次澄清「**核心需求是避免誤按而登出帳號**」, 才意識到 framing 該是「destructive action 需要 confirm」不是「修 bug」。

**未來規則**: 
- user 給「現象」(token 檢驗開了登出不了) ≠ user 要的「fix」(誤按防護)
- destructive UX 一律 popup 三按鈕分明 (取消 / 安全選項 / 推薦預設), 不一按即發
- ForceRemove 已經有 popup, 一般 Logout 反而沒有 → 反直覺, 該補
